# 디자인

초기 화면은 브랜드, ‘전·월세 세입자를 위한 AI 수리 가이드’, ‘이거, 누가 / 고쳐야 하지?’, 두 줄 설명, 세 유형의 범위, ‘내 상황 확인하기’ 하나의 주요 버튼으로 구성한다. 홈에 카드 목록·통계·후기·가격·큰 그림을 넣지 않았다.

## 토큰
`src/styles/tokens.css`: 배경 #F8FAFC, 표면 #FFFFFF, 본문 #111827, 보조 #4B5563, 강조 #2563EB, 선 #E5E7EB. 본문 16px, 보조 14px, 홈 제목 36px, 화면 제목 32px. 단일 열 480px 상한, 좌우 24px, 버튼 56px, 선택·보조 액션 48px 이상. 시스템 글꼴, 선형 SVG 증상 아이콘, 자체 컴포넌트 사용. TDS·토스 폰트 없음.

위험 색은 안전·오류에만 사용한다. 라디오 선택은 테두리·체크·접근성 상태를 함께 표시한다. 페이지 전환 시 제목에 포커스를 옮기고 textarea는 명시적 label을 가진다. 가로 오버플로를 검사하며 safe-area 패딩을 넣었다. 고정 CTA가 없어서 입력과 겹치지 않는다. reduced-motion에서는 로딩 회전을 중지한다.

## 캡처·확인
`docs/screenshots/`의 home/questions/result/message 각 360x640, 390x844, 1440x900 PNG. 긴 입력·로딩·오류·확대 결과도 세 크기로 캡처한다. 홈 360x640에서 제목·설명·CTA가 스크롤 없이 보이는지 bounding box로 검사했다. 홈·질문·결과 axe 검사에서 검출된 위반 0건. 이는 모든 접근성 기준의 완전 충족 보장이 아니다.

200% 테스트는 루트 글꼴을 16→32px로 확대해 수행했다. 브라우저 UI 확대나 OS 글꼴·실기기 키보드 테스트와 구분한다. 390x400으로 키보드가 열린 것과 유사한 가용 높이를 검사했지만 실제 iOS/Android 키보드는 미검증이다.

직접 캡처 검토 후 긴 한국어 단어의 줄바꿈을 개선했다. 테스트에서 발견한 삭제 요청 오류도 수정했다. 디자인의 3초 이해도는 캡처로 입증하지 않았다.

## 사람 테스트 프로토콜 — 미실행
목표 사용자 5명에게 홈을 3초 보여준 뒤 가린다. 누구를 위한 서비스인지, 어떤 문제를 해결하는지, 무엇을 누르는지 각각 묻는다. 진행자는 답을 유도하지 않고 익명으로 핵심 이해 여부만 기록한다. 목표 4/5는 팀의 사용성 기준이며 통계적 성과가 아니다.
