# 최소 이용 이벤트

`usage_metrics`에는 원문·주소·계약·토큰 없이 event/mode/latencyMs/inputTokens/outputTokens/costUsd/failureCode 형식의 허용 데이터만 저장한다. 실패 코드는 현재 분석 행의 failure_code에도 기록한다. 데모는 mode=mock, 실제는 mode=live로 구분한다.

| 이벤트 | 정확한 발생 지점 | 분모·중복 기준 |
| --- | --- | --- |
| start | 처리 고지 확인 후 서버 게스트 발급 | 게스트당 1회. 홈 CTA 클릭이나 모든 방문자 수가 아님 |
| questions_complete | 검증된 입력으로 분석 행을 생성한 때 | 분석 ID당 1회. 같은 멱등키 재전송 제외 |
| analysis_success | 일반 공급자 결과를 검증하고 저장한 때 | 분석 ID당 1회. 위험·범위 규칙 출력은 제외, live만 실제 AI 성공 집계 |
| copy_success | navigator.clipboard.writeText resolve 후 | 결과당 1회. 발송·수리·분쟁 해결 아님 |
| feedback | 완료 결과에 피드백 저장 성공 | 결과당 1회, 답변은 마지막 상태로 갱신 |

연결 손실로 복사 성공 이벤트 전송이 실패하면 복사 자체는 성공했어도 통계는 누락될 수 있다. 전달되지 않은 이벤트를 추정해 채우지 않는다. 삭제·만료 시 사용자별 이벤트도 삭제된다. 따라서 장기 코호트 전환율 통계에 적합하지 않다.

전환을 계산한다면 동일 모드·동일 관찰 기간의 보존된 게스트/결과를 분모로 명시한다. 데모를 live 비용·성능 집계에 섞지 않는다. 실제 이용시간·해결률·전환율·정확도는 관찰하지 않았고 UI에 표시하지 않는다.
