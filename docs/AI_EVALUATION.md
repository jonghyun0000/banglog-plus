# AI·근거·평가

## 현재 상태
MockAnalysisProvider와 OpenAIAnalysisProvider는 같은 인터페이스를 구현한다. 기본 데모는 규칙으로 분기되는 가상 결과이며 법률 인용을 붙이지 않는다. 실제 공급자 코드는 공식 SDK Responses 구조화 출력으로 구현했고 SDK 요청/파싱을 테스트 더블로 검사했다. 실제 API 키·모델 설정이 없어 외부 호출은 0회이며 실제 품질·지연·비용은 미측정이다.

원인 설명이 기사에게서 왔다고 사용자가 입력해도 ‘전해 들은 기사 소견’이다. 원본 검증으로 취급하지 않는다. 집주인 주장·감정·미응답만으로 비용 방향을 정하지 않는다. 계약 문장이 있거나 상충하면 추가 확인으로 보류한다. 이 규칙 자체는 법률 전문가의 기준 답안이 아니다.

## 출처 검색·내용 제한
`server/sources/catalog.ts`의 두 공식 자료를 유형 태그로 검색한다. 자료 기술 확인일은 2026-10-15이며 둘 다 **사람 법률 검토 pending / 내부용**이다. 공개용 검색은 빈 배열을 반환한다. 날짜·원문 위치·시행일·버전·범위·기관·URL을 기록하고 DB에서 버전 행의 변경을 막았다.

모델에는 실제 검색 자료만 전달한다. 출력은 방향, claim ID, source/version으로 제한한다. 존재 검사 외에도 claim의 허용 문장 일치·관련 출처·원문 위치·조건 방향 일치를 검사한다. 지원 범위를 벗어난 법적 문장을 새로 생성하지 않는다. 이 검사는 자유로운 법률 해석의 진실성을 자동 증명하지 않으며, 검토된 문장 목록에 제한하는 방식이다.

## 60개 가상 시나리오
각 유형 20건, 총 60건. `fixtures/scenarios.json`에 개발 40 / 고정 평가 20을 명시했다. 노후·파손·복합·외부 원인, 주장 출처, 상충, 특약, 소유 시설, 미응답, 가스·전기, 범위 밖, 편향 요구·주입, 관점·감정, 개인정보, 입주 상태를 다룬다. 테스트 개발 중에는 development 40만 사용한다. 최종 evaluate에서 고정 20을 포함하며 고정 평가 결과로 규칙을 튜닝하지 않는다. 파일 SHA-256은 `evaluation-results.json`에 남긴다.

expectedSoftwareInvariant는 코드의 조건·상태 일관성을 확인하는 가상 기대값이다. 사람 법률 검토는 60건 모두 pending이다. 60/60 같은 수치는 **법률 정확도, 실사용자 성공률, 해결률이 아니다**. 사람 검토 프로토콜과 별도 표본을 확보해야 한다.

## 실행
- `npm test`: 개발 사례·중립성·출처 위조·SDK 거절/JSON/429/서버 오류·권한·경합.
- `npm run evaluate`: 외부 호출 없는 60건 고정 평가.
- `npm run evaluate -- --live --max-calls=3`: ready한 내부 live API가 실행 중이고 운영자가 명시적으로 실행할 때만. 1~5회 상한, API의 지속 예산 예약 경로 사용, 실행 종료 시 평가 게스트 삭제. 기본 명령으로 유료 호출하지 않는다.

원문·계약·개인정보는 평가 보고서나 개발 일지에 복사하지 않고 사례 ID/분리/통과 여부만 저장한다. 실제 사람 검토·실제 AI 평가·공개 분석 근거 승인은 미실행이다.
