# 사진 관찰과 증거 촬영 안내

2026-11-11 · 방로그 Plus v1.5 후속 작업 · 별도 브랜치 `feature/photo-evidence-coaching` · 로컬 구현

## 변경 전 확인

| 가설 | v1.5 기준 `a901bc5`에서 확인한 동작 |
| --- | --- |
| 기본 개발 실행은 모의 응답 | `server/config.ts`의 기본값은 mock이고, 별도 환경을 로드하는 `dev:ai`는 live를 지정한다. 기본 개발 실행은 사진 API를 호출하거나 사진 관찰을 모의 생성하지 않고 `skipped`로 처리했다. |
| 실제 사진 관찰은 코드만 반환 | `server/ai/photo.ts`와 `shared/photo.ts`의 응답은 관련성·선명도와 최대 여섯 개 징후였다. 사진별 요약과 문자 값은 없었다. |
| 모든 문자 읽기를 금지 | 기존 공급자 프롬프트에 `Do not … transcribe any text`가 있었다. |
| 해상도가 low | 실제 Responses 요청에 `detail: "low"`가 지정돼 있었다. |
| 최종 안내에서 사진이 잘 드러나지 않음 | `server/ai/provider.ts`는 징후 이름을 검색어와 생성 입력에 이미 연결했다. 개별 사진 위치, 읽힌 기기 정보와 상황별 추가 촬영 안내는 제공할 수 없었다. |

실제 공급자 경로에는 서버의 live 설정, 모델, 키, DB와 준비 조건이 필요하다. 사진은 별도 선택 동의가 필요하다. 이 변경에서 새로운 운영 환경을 조사하거나 수정할 필요가 없었다.

## 사용 흐름

1. 사진을 추가하면 첨부 완료가 표시된다. 이미 찍었거나 갖고 있는 자료를 선택할 수 있다. 사진 전송 동의를 별도로 확인한다.
2. 결과에는 실제 AI 관찰, 확인하기 어려움, 실패, 미실행, 개발용 모의 처리가 구분된다. 한 번에 최대 세 장을 보내며 사진 번호 순으로 관찰을 보여준다.
3. 보일러·관련 가전의 사진에서 오류 표시나 제조일 라벨이 명확할 때 후보를 보여준다. 입력란에서 값을 확인·수정하고 그 값으로 수리 안내를 다시 요청할 수 있다. 다른 값이 읽힌 사진을 자동으로 하나로 합치지 않는다.
4. 전체·근접·표시부·제조연월 등 현재 빠진 자료를 최대 세 개 제안한다. 위험 상태에서는 기존 안전 화면을 우선하며 추가 촬영을 권하지 않는다. 이미 확인한 자료는 목록에서 제외한다.
5. 같은 사진의 실패는 현재 세션의 소유권과 기존 입력 지문을 확인한 뒤 한 번 재요청할 수 있다. 다시 실패하면 화면의 기존 안내와 문구를 보존한다. 기기 정보 확인은 사진을 재전송하지 않고 서버에 저장된 관찰을 사용한다.

## 처리와 보관

- 사진과 선택 문제 유형만 이미지 API에 전달한다. 공급자 응답은 사진 순서별로 엄격히 검사한다. 화면의 한 줄 관찰과 촬영 문구는 검증된 위치·징후·구도 코드로 서버가 조합한다. 이미지 안의 문장이나 자유 OCR은 결과에 포함하지 않는다.
- 오류코드는 짧은 숫자·영문 조합으로 검증하며 기기 오류 표시가 명확할 때만 취한다. 제조연도는 제조일 라벨 확인과 연도 범위가 맞을 때만 취한다. 후보와 사용자 확인값을 구분한다.
- 원래 보고한 사실과 사진 관찰, 사용자 확인값을 구분한다. 징후·관찰은 근거 검색과 점검 질문에 반영한다. 결과 생성은 기존의 승인 자료 검색과 인용·조건 검증을 거친다. 코드별 원인 사전을 새로 추가하지 않았으므로 기기 정보는 점검 자료로만 쓰인다.
- 브라우저에서 JPEG로 재인코딩하여 메타데이터를 제거한다. 서버도 JPEG 헤더의 변 길이 1024px 한도를 검사한다. 최대 3장, 장당 데이터 문자열 400,000자와 요청 한도를 유지한다. 이미지는 `detail: "auto"`, `store: false`, 자동 재시도 0으로 요청한다. 기존 호출 수·토큰·비용 예산에서 사진 호출 한 건에 16,000토큰을 예약하고 반환된 사용량을 기존 집계에 포함한다. 실제 과금과 판독 결과는 모델과 사진에 따라 달라진다. [OpenAI 이미지 입력 공식 문서](https://developers.openai.com/api/docs/guides/images-vision)
- 원본은 분석 DB·회원 기록·일반 로그에 넣지 않는다. 로컬 수선 기록장에 복사하려면 종전과 같이 별도로 선택하고 동의해야 한다. 사진 관찰과 확인값은 기존 결과 JSON에 포함돼 회원 기록과 기기 수선 기록에서 다시 열 수 있다. 기존 기록의 관찰 형식은 계속 읽으며 출처 필드가 없는 경우 ‘이전에 저장한 사진 관찰’로 표시한다. 촬영·발견·전달 시각과 분석 요청 시각은 연결하지 않는다.
- 사진에서 개인정보를 자동으로 가리지는 않는다. 이름·주소·얼굴·연락처·일련번호·QR 등을 첨부 전에 제거하도록 안내한다. 오류코드와 제조연도는 형식 검사와 화면 후보 표시로 오독의 영향을 줄인다. 사진 속 모든 식별 정보의 탐지·차단이나 실제 모델 정확도를 보장하지 않는다. 처리 고지 버전은 `2026-11-11.v7`이다.

## 검증 범위

- 단위·API 217건 및 타입 검사·린트·포맷 검사 통과. 사진별 순서와 관찰, 명확한 오류코드와 제조일, 온도·다른 날짜·흐린 사진·무관한 사진, 합성 연락처와 명령문을 다루는 응답, 잘못된 개수·크기, 429/실패와 이전 결과 보존을 확인했다. OpenAI SDK 요청 경로는 가로챈 응답으로 확인했다.
- 격리 PostgreSQL 32건 통과. JSONB를 거친 재요청의 멱등 처리, 기존 결과 재조회, 사진 관찰의 회원 기록 저장, 원본 미저장을 확인했다.
- 운영 방식 빌드 및 로컬 데모 빌드와 데모 8건 통과. 고정 사례 60/60, SHA-256 `788623c33878e00159bff286b2ca7374f64493ebe69366da29aca76524fd9bad`.
- 새 코드의 실제 GPT 판독, 실제 휴대전화와 운영 회원 계정 검증은 미실행이다. 비개인정보 합성 사진을 사용한 Chromium 검사와 SDK·API 검사는 실제 모델의 판독률을 입증하지 않는다. 유료 검증의 승인 범위와 한도를 이 작업에서 확인할 수 없어 외부 호출은 사용하지 않았다.
- 로컬에서 `npm run dev`로 열면 ‘개발용 모의 분석’ 표시를 확인할 수 있다. 실제 설정 확인 시 `dev:ai`는 별도의 로컬 설정과 DB를 요구한다. 공급자 응답 검증과 사용량 추적에 모델 변경은 필요하지 않다. 운영 Vercel 반영과 원격 DB 변경은 미실행이다.
- Chromium 53건 통과. 사진 첨부 완료와 응답 대기 표시, 실패 후 한 번 재요청과 사진 없이 진행, 오류코드 수정 뒤 기존 문구 보존, 기기 수선 기록 조회를 확인했다. 360×640, 390×844, 1440×900에서 가로 넘침과 axe 위반은 모두 0건이었다. 초기 브라우저 테스트는 문구 화면의 다른 기록 버튼을 찾아 시간 초과했고, 올바른 버튼으로 기록 조회까지 확인한 뒤 전체를 다시 통과했다.
- 스크린샷과 최종 테스트 출력은 이 작업 폴더의 `.local/photo-verification/`에 보관했다. 노션 프로젝트 개요·PRD·날짜별 활동 기록에 로컬 구현과 검증 범위를 추가했다.
