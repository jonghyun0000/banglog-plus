# 방로그 Plus 팀 피드백 반영과 발표 기획안

2026년 10월 20일 팀 의견을 10월 21일 제품에 반영했다. 방로그 Plus는 주택 세입자가 수리 문제를 정리하고, 점검 요청 상대와 비용 협의에 필요한 자료를 확인한 뒤 연락 문구를 만드는 서비스다. 이번 초안의 핵심은 수리 전 소통 과정의 불확실성을 줄이는 것이다.

## 개요와 목적

대학생 자취생·사회초년생을 우선 검증 대상으로 삼는다. “무엇이 고장 났는가”만으로 비용 부담자를 단정하기 어렵고, 연락을 하려 해도 어떤 내용을 준비할지 모를 수 있다는 문제 가설에서 출발한다. 원인·입주 상태·제공 주체·계약·상대방 설명을 구분해 다음 행동을 제시한다.

목표는 자동 책임 판정이 아니라 세입자가 점검 요청과 비용 협의를 구분해서 진행하도록 돕는 것이다. 분쟁 감소나 법률 정확도 향상은 아직 검증한 성과가 아니다.

| 신축 하자보수 | 일반 임대차 수리 안내만 포함, 시공사 청구는 후속 범위 | 청구 주체·하자보증기간·분양계약은 별도 설계 필요 |

## 이용 흐름과 시연

문제 선택 → 7단계 상황 확인 → 입력 검토·수정 → 점검 상대와 조건별 안내 → 문구 편집·복사 → 선택 피드백·삭제.

발표 시연은 “장판에 찍힘이 있어요”로 시작한다. 입주 당시에도 있었는지, 원래 있던 장판인지, 누가 원인을 설명했는지 답한다. 결과에서 입주 기록 비교와 부분 보수 확인 목록을 보여주고, 비용을 확정하지 않은 점검 요청 문구를 복사한다. 다음으로 배수 역류와 옵션 냉장고 화면을 짧게 보여주면 확장성을 설명하기 쉽다.

## 차별화 가설

당근의 업체·견적 연결, 다방의 매물·계약, 자리톡의 임대관리와 접점이 있다. 경쟁 기능이 전혀 없다는 주장은 피한다. 방로그 Plus는 다음 세 가지를 한 흐름으로 묶는 제안이다.

1. 실제 증상, 사용자 추측, 전해 들은 기사 소견, 상대방 주장을 구분한다.
2. 점검을 요청할 상대와 최종 비용 부담을 나누어 설명한다.
3. 확인해야 할 기록과 차분한 요청 문구를 바로 만든다.

확보할 경쟁력은 질문의 정확성·정보의 신뢰성·소통의 편리함이다. 현재 이 조합의 수요와 경쟁 우위는 인터뷰로 검증할 가설이다. [공식 자료 비교 및 출처](RESEARCH.md)를 참고한다.

## 독립 웹과 플랫폼 연동 방향

**이번 제출은 독립 웹 MVP로 진행한다.** 링크 하나로 로그인 없이 시연할 수 있고, 팀이 질문과 안내를 직접 수정하며 사용자 반응을 확인할 수 있기 때문이다.

| 형태 | 기대효과 | 필요한 후속 작업 |
| --- | --- | --- |
| 독립 웹 | 빠른 시연·질문 개선·학교 발표 | 사용자 유입, 신뢰 형성, 서비스 운영 주체 마련 |
| 자리톡 내 수리 상황 정리 기능 제안 | 임대관리 이용 중 수리 소통으로 연결 | 실제 이용 흐름 조사, 제휴·API·동의·역할 설계 |
| 당근 부동산·생활 서비스와 연결 제안 | 지역 업체 문의 전에 기록 정리 | 입점 가능성, UI 위치와 이용 조건 확인 |
| 다방 계약 후 거주 지원 기능 제안 | 집 구하기 이후 생활 지원 | 제휴·계약 데이터 접근 범위·소통 경로 검증 |

‘당근 월세결제 옆’은 팀의 배치 아이디어이며 해당 메뉴 위치·연동 가능성을 확인한 사실이 아니다. 제휴 계약이나 플랫폼 내 실제 기능은 아직 없다. 수리업체 추천 수수료 모델을 검토할 때도 책임 안내가 업체 전환을 유도하지 않도록 분리해야 한다.

## 현재 구현과 다음 검증

현재 공개 사이트는 브라우저 안에서 동작하는 규칙 기반 데모다. 실제 AI 분석·서버 DB 저장·수리업체 연결·자동 발송·사진 판독은 공개 사이트에서 제공하지 않는다. 입력과 결과는 새로고침하면 사라지고, 피드백 역시 운영자에게 전달되지 않는다. 서버·AI·DB 코드는 별도 내부 검증용으로 존재한다.

다음 검증은 5명 내외의 세입자 인터뷰와 사용성 관찰로 시작한다. 본인 경험을 식별정보 없이 요약해 질문을 이해하는지, 점검 요청 상대와 비용 부담을 구분하는지, 문구를 수정해 실제로 쓸 의향이 있는지 확인한다. 목표는 5명 중 4명이 두 개념을 구분하는 것이며 현재 달성 수치는 없다. 법률 전문가에게 질문의 누락과 판례 요약을 별도로 검토받는다.

제반사항은 출처와 확인일 관리, 개인정보 최소 입력, 결과의 임시 보관, 모델 비용·오류 대응, 책임 확정 표현 금지다. 담당자 배정·일정·예산은 팀에서 정해야 하며 확정한 사실처럼 기재하지 않는다.

## 발표 순서와 결론 문장

5분 발표라면 문제·목적 1분, 경쟁 서비스와 차별화 1분, 장판 사례 시연 2분, 검증 계획과 범위 1분으로 구성한다.

“방로그 Plus는 세입자가 수리를 요청하기 전에 증상과 기록을 정리하고, 비용을 협의할 준비를 돕습니다. 이번에는 독립 웹으로 사용성을 검증하고, 이후 기존 임대관리·부동산 서비스에 연결할 가능성을 살펴보겠습니다.”
